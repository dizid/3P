Zooming out from one click

A view is surprisingly thin

A view doesn’t do much on its own. It just arranges other components and decides which one is visible. Here’s the entire 10-10-10 view, side-by-side with plain English.

CODE — TenTenTenView.vue 
<template>
  <div class="min-h-screen py-8 px-4">
    <div class="max-w-4xl mx-auto">
      <ToolHeader
        icon="&#9200;"
        title="10-10-10 Rule"
        description="How will you feel in 10 minutes, 10 months, and 10 years?"
        color="#3b82f6"
      />
      <GutCheck v-if="!showResult" v-model="gutFeeling" />
      <TenTenTenForm v-if="!showResult" @complete="showResult = true" />
      <TenTenTenResult v-else @back="showResult = false" @reset="reset" />
    </div>
  </div>
</template>
PLAIN ENGLISH

Begin the template — the visible layout.

Outer wrapper: full screen height, some padding.

Inner box: max width, centered horizontally.

Render the ToolHeader set piece with these settings…

…use a stopwatch icon…

…show the title…

…show the description underneath…

…tint it blue. These are all props — data passed down to the child.

Self-closing tag — ToolHeader has no children.

Show GutCheck only if the result isn’t showing yet. v-model lets GutCheck read AND write gutFeeling.

Show the form only if we’re not on the result screen. When it emits complete, flip the switch to true.

v-else: show the result screen instead. Back and reset events bubble up to the view.

Close the inner box.

Close the outer wrapper.

End of the template.

🔍
Notice what’s missing

No scoring math. No saving. No API calls. A view composes; it doesn’t compute. The heavy lifting lives in stores and services.

The key insight

The button never talks to the database directly. It talks to its script supervisor (the store), who handles local storage, then delegates the remote sync to a Netlify Function. Each actor only knows its neighbor.
